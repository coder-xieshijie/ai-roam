REUSABLE SKILLS

dev-skills

把开发中反复用到的判断与方法，整理成六个可手动调用的 Skills。
从解释概念、评审方案，到收敛决策、编写计划，再到读懂代码变化。

查看源码↗安装与使用↗

介绍复核于 2026-09-22 · 查看依据版本 be19ce4

把方法留下来

当前公开六个 Skill，覆盖概念解释、评审判断、技术方案、决策收敛、执行计划与变更阅读。每个 Skill 都可独立使用，按当前任务选择，不要求依次调用。

全部采用手动触发：Codex 用 $skill-name，Claude Code 用 /skill-name。它们提供可复用的工作指引，实际输出仍需结合任务检查。

01 / 把概念讲清楚

explain-as-fool

面向没有相关知识的读者，从基础解释技术概念，直接、准确地表达。

$explain-as-fool 解释一下什么是线程池
阅读 Skill 原文↗

02 / 让评审有依据

review-rules

检查代码、设计与已有评审建议，结合需求、现有实现和失败场景判断问题与修复方案。

$review-rules 复核这条评审意见，说明依据与最小必要改动
阅读 Skill 原文↗

03 / 让方案可独立阅读

design-for-review

将需求和设计材料整理成技术评审文档，讲清问题、完整流程、改动范围与关键取舍。

$design-for-review 根据已确认的设计，整理一份可独立阅读的评审文档
阅读 Skill 原文↗

04 / 留下明确的约定

core-spec

讨论结束后，把已确认的决定与约束收敛到一份 spec；突出核心决定，完整保留影响实现的边界。

$core-spec 将当前讨论收敛为核心决策与约束，保存到 docs/feature-spec.md
阅读 Skill 原文↗

05 / 把决定变成计划

plan-for-agents

把需求和已确认决策展开成 Agent 可独立执行的完整计划，覆盖步骤、边界、产物与验收证据。

$plan-for-agents 根据已确认的 spec，编写可独立执行的完整 plan
阅读 Skill 原文↗

06 / 读懂 AI 写的代码

mr-for-human

先看 PR/MR 的核心设计和关键决定，再沿主流程下钻到执行逻辑、失败边界与具体源码。

$mr-for-human 带我读懂这个 PR，给出从核心设计到源码的阅读路线
阅读 Skill 原文↗

怎样用得更好

先明确任务范围，再调用需要的 Skill。例如评审哪个分支、是否允许修改、最终要交付什么。Skill 会沿用当前任务的范围与执行要求。

仓库 README 给出了 Codex 的 $skill-name 和 Claude Code 的 /skill-name 调用示例。安装位置和实际支持情况请以宿主及仓库文档为准。
