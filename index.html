第一章 / 把方法留下

dev-skills

定好要什么，
再放手交给 Agent。

从需求到验证过、可合入的 PR：一套给编程 Agent 用的 Skills。先给仓库搭一个 Agent 能自己启动、操作、观察的验证环境；之后每个需求由一个 Agent 从头做到尾，在运行的应用里证明结果，再由另一家模型独立验证。人只在三处介入：确认决定，确认验收标准，合入前读一遍决定清单。

第二章 / 最初的工具

Agent Lord

从调度更多 Agent，
到先让一个 Agent 做对。

这条工作流的起点：一个在主会话里调度多个编程 Agent 的工具。8 月写成，把任务派给 Claude Code、Codex 和 MCode，让它们并行干活、互相评审，每一步都有记录。用下来发现，卡住交付的不是 Agent 不够多：它们没法自己运行产品来证明做对了，已经定下的事也会在一次次交接中丢失。9 月底起，新需求改走 dev-skills 的流程。

  • 交叉评审
  • 计划交叉评审
  • 计划到实现
看看它做过什么
